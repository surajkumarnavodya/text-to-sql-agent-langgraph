# --- Production authentication (optional, see security/oidc.py, docs/AUTHENTICATION.md) ---
# OIDC/JWT validation for `AUTH_MODE` beyond the legacy static bearer token
# (api/auth.py's pre-existing API_AUTH_TOKEN check, kept unchanged and still
# supported). The `crypto` extra pulls in nothing new at runtime --
# `cryptography` is already present transitively (via `pyodbc`'s own deps) --
# but is declared explicitly so this dependency is self-contained rather than
# silently relying on another package continuing to pull cryptography in.
# `PyJWKClient` (this module's actual JWKS-fetch/cache/key-rotation
# mechanism) is part of the base package, not the extra.
# Bumped 2.14.0 -> 2.15.1 (2026 security remediation pass) for
# CVE-2026-101918/GHSA-42vr-xj54-vc7v: `PyJWKClient.get_signing_key_from_jwt`
# (called directly at security/oidc.py's `jwk_client.get_signing_key_from_jwt(token)`
# call site, before signature verification) only catches `ValueError` around
# its pre-verification payload parse, not `RecursionError` -- an
# unauthenticated caller sending a deeply, recursively nested JWT payload to
# any OIDC-protected route raises an uncaught exception (caught by this app's
# own global exception handler, so not a process crash, but a real
# unauthenticated DoS/error-rate vector nonetheless). Fixed in 2.15.0.
pyjwt[crypto]==2.15.1
